이미지 포맷 비교: WebP, PNG, JPG, BMP

같은 사진이라도 저장 형식에 따라 용량과 화질, 투명 배경 지원 여부가 달라집니다. 업로드 폼이 특정 확장자만 받거나, 로고 배경이 하얗게 깨질 때 형식 선택이 핵심입니다. 이 글은 네 가지 형식을 용도 중심으로 비교합니다.

JPG: 사진에 강하고 용량이 작다

JPG(JPEG)는 사진처럼 색이 부드럽게 변하는 이미지에 잘 맞습니다. 손실 압축이라 용량을 크게 줄일 수 있지만, 저장을 반복하면 경계가 뭉개지거나 블록 노이즈가 생길 수 있습니다. 투명 배경을 지원하지 않아 PNG 로고를 JPG로 바꾸면 투명 영역이 단색으로 채워집니다. 웹 썸네일·메일 첨부·SNS 업로드에 가장 흔합니다.

PNG: 선명함과 투명이 필요할 때

PNG는 무손실에 가깝게 저장할 수 있고 투명(알파)을 지원합니다. 아이콘, 로고, UI 스크린샷, 글자가 많은 이미지에 유리합니다. 대신 사진 용량은 JPG·WebP보다 커지기 쉽습니다. ‘배경을 살려야 하는 로고’라면 PNG를 기본으로 두는 편이 안전합니다.

WebP: 웹에서 용량을 더 줄이고 싶을 때

WebP는 비슷한 체감 화질에서 JPG·PNG보다 용량을 줄이는 경우가 많습니다. 최신 브라우저 지원도 넓어졌지만, 일부 구형 프로그램·인쇄 워크플로는 아직 열지 못할 수 있습니다. 웹 성능이 중요하고 수신 환경이 최신이라면 WebP를 시험해 볼 가치가 있습니다. 호환성이 최우선이면 JPG/PNG로 되돌리면 됩니다.

BMP: 단순하지만 무겁다

BMP는 구조가 단순해 오래된 도구·임베디드 환경에서 요구되기도 합니다. 압축이 약하거나 없는 경우가 많아 용량이 큽니다. 일상적인 웹·모바일 공유용으로는 거의 쓰지 않고, ‘그 프로그램이 BMP만 받는다’는 조건이 있을 때 변환 대상으로 씁니다.

선택 체크리스트

사진 공유·용량 절감 → JPG 또는 WebP. 투명 로고·UI → PNG. 최신 웹 성능 → WebP 우선 검토. 구형 소프트웨어 → BMP 또는 JPG. 확신이 없으면 원본을 남긴 채 WebToolBay 이미지 형식 변환으로 여러 결과를 비교해 보세요. 자르기가 필요하면 변환 전에 이미지 자르기·회전으로 구도를 맞추는 편이 재작업을 줄입니다.

용량·화질을 비교하는 현실적인 방법

이론보다 결과물을 나란히 보는 편이 빠릅니다. 같은 원본에서 JPG·WebP·PNG를 만든 뒤 파일 크기와 확대 시 경계선·글자 선명도를 비교하세요. 사진 계열은 작은 용량 차이가 체감 화질로 잘 안 드러나는 경우가 많고, 글자·아이콘 계열은 PNG가 유리한 경우가 많습니다.

이미 배포된 JPG를 다시 JPG로 여러 번 저장하는 ‘재압축’은 피하세요. 편집이 남았다면 가능한 한 원본 또는 PNG 단계에서 끝내고, 마지막에만 배포용 포맷을 만듭니다.

업로드 실패를 줄이는 실무 팁

사이트·메일이 ‘5MB 이하 JPG만’처럼 제한하면, 먼저 해상도를 필요한 크기로 줄인 뒤 형식을 맞추세요. 투명 로고를 JPG로 강제 변환하면 배경이 깨지므로, 그런 폼에는 PNG를 허용하는지 확인하고 아니면 배경을 단색으로 합성한 JPG를 준비합니다.

실무에 남기는 포인트

포맷 선택은 취향이 아니라 배포 채널의 제약입니다. 상대 시스템이 무엇을 받는지 먼저 확인하고, 원본은 별도 보관하는 습관이 사고율을 낮춥니다.

웹 성능이 중요하면 WebP를 시험하고, 인쇄·아카이브·투명도가 중요하면 PNG, 범용 사진 공유는 JPG를 기본값으로 두면 의사결정이 빨라집니다.

한 가지 더

이메일 첨부처럼 수신자 환경이 제각각이면 JPG가 무난한 기본값입니다. 내부 디자인 에셋은 PNG로 보관하고, 웹 배포본만 WebP/JPG로 뽑는 2단 구조가 협업에서 갈등을 줄입니다. 변환 전후 해상도(가로·세로 픽셀)를 메모해 두면 재작업을 피할 수 있습니다.

브라우저 Canvas로 변환할 때 겪은 제약

WebToolBay 이미지 변환은 서버 업로드 없이 Canvas로 다시 그립니다. 테스트해 보면 Safari(맥·아이폰 기본 브라우저)는 Canvas에서 WebP를 만들 때 PNG로 떨어지는 경우가 있어, 도구가 WebP를 지원하지 않으면 선택지 자체를 막도록 만들었습니다. ‘저장했는데 확장자만 WebP’ 같은 사고를 막기 위한 조치입니다.

BMP는 브라우저가 Canvas로 직접 인코딩하지 못해, 픽셀을 읽어 파일 헤더를 직접 조립합니다. 그래서 BMP는 용량이 커지기 쉽고, 일상 공유용보다는 구형 프로그램 호환용으로 쓰는 편이 맞습니다. 품질 슬라이더는 JPG·WebP 같은 손실 포맷에만 적용됩니다.

화질을 지키는 습관

손실 포맷끼리 반복 변환하는 것은 피하세요. 가능하면 편집은 PNG나 원본에 가깝게 하고, 배포용으로만 JPG/WebP를 만듭니다. 매우 큰 이미지는 기기 메모리 한도에 걸릴 수 있으니, 필요한 해상도로 먼저 줄인 뒤 변환하는 것도 방법입니다.
